# 上线记录

一次上线一份，记录**实际发生了什么**：做了哪些需求、哪些没做、偏离方案的地方、
实测数据、以及验证不了的部分。

与另外两类文档的分工：

| 目录 | 回答的问题 | 改动频率 |
| --- | --- | --- |
| `docs/adr/` | 为什么这样定 | 低，改要推翻 |
| `docs/design/` | 打算怎么做 | 中，方案演进时改 |
| `docs/launch/` | 实际做成了什么 | 只增不改，一轮一份 |

写进来的标准：**下一轮开工的人需要知道的东西**——没做完的口子、临时方案、
实测基线（下轮回归时拿来对比）、以及当时验证不了的部分。
纯粹的过程流水不写。

命名：`YYYY-MM-DD-<一句话主题>.md`。
