# CSI 改写规范

- 依据：[ADR-0007](../adr/0007-copy-conventions.md)（决策与出处）、[ADR-0010](../adr/0010-ai-assisted-writing.md)（定稿标准）、[ADR-0016](../adr/0016-course-conventions-scope.md)（长度上限与压缩顺序，提议中）
- 适用：Experience 每条、项目卡片、L2/L3 文档开头、简历 bullet

## 结论

一条 bullet 要过关，**三段的信息必须都在**：

- **Challenge** — 当时的**业务**困境。不是技术任务。
- **Solution** — 架构/方法上的选择，**并且点出放弃了什么**。
- **Impact** — 结果，尽量带可核验的量。

**三条同时也是三道否决线**：写不出取舍的不合格（ADR-0007 §1）；
拿不出结果的不写（约束 1）；数字不可核验的宁可不写（约束 2）。

**CSI 是内容检查表，不是句式模板。** 最终文本应当是自然行文，
不是"挑战……方案……成果……"三句并排的排比（ADR-0007 后果第 1 条、ADR-0010）。

## 改写流程

1. **先找 Challenge，不要先改句子。** 原句通常只有 Solution 的一半。
   问："当时不做这件事，业务会怎样？"答不上来，说明素材不够——
   回 `Career/Experience/` 补，不要靠润色填补。
2. **把 Action 收紧成 Solution。** 问："当时还有别的做法吗？为什么没选？"
   这一问的答案就是取舍。没有答案 = 不合格，不是"写得不够好"。
3. **补 Impact，核验数字。** 数字只能来自本人提供的事实，
   **不得补全、推测或"合理化"**（ADR-0010）。
4. **合并成自然句子。** 三段的信息在，但不必是三个分句、更不必对仗。
5. **交本人定稿。** 对外文本没有 AI 直接定稿的通道（ADR-0010）。

## 反例

以下示例均为**虚构**（FR-11.5）。

### 反例 1：只有 Solution

> Implemented a distributed caching layer using Redis and Kafka.

做了什么很清楚，但不知道为什么要做、做完怎么样。**这是技术执行者的语法。**

### 反例 2：有结果，但没有取舍

> 面对订单查询变慢的问题，引入 Redis 缓存，把响应时间从 800ms 降到 50ms。

三段看似齐了，但 Solution 段只是"引入了 X"。
读者无法判断这是一个设计决策还是一次照搬。**不合格。**

### 反例 3：改成了排比

> **Challenge** 订单查询在峰值下超时。
> **Solution** 设计冷热分离的两层缓存，放弃强一致以换取写入吞吐。
> **Impact** P99 从 800ms 降到 50ms，峰值零超时。

信息全对，但**这是检查表的形态，不是文案的形态**。
站点和简历上不能这样并排三句——ADR-0010 要防的正是这种一眼可辨的机器结构。

### 反例 4：数字不可核验

> 使系统性能提升约 10 倍，为公司节省大量成本。

"约 10 倍"没有基线，"大量成本"不是数字。**宁可不写**（ADR-0007 约束 2）。

## 合格的样子

同一条素材（虚构），自然行文：

> 订单查询在大促峰值下频繁超时，根因是热点数据与全量数据走同一条缓存路径。
> 我做了冷热分离的两层缓存，代价是热层放弃强一致——业务上确认了这一点可接受。
> 改造后 P99 从 800ms 降到 50ms，当年大促期间零超时。

三段信息都在：困境（业务的，不是"任务是加缓存"）、取舍（放弃强一致，且说明了为什么可接受）、
可核验的结果。但读起来是一段话，不是一张表。

## 与站点文案的关系

- **关键词共用一套**（ADR-0007 §2）。简历里用的动词和名词，
  要和站点 Hero、板块标题、卡片问题句是同一批。改一边就要同步另一边。
- **事实只有一份**。简历 bullet 引用的事实以 `lib/content/` 为准；
  发现不一致时先查证再改，**未核实的时间不要擅自改站点**（`TODO.md` §2）。
- **折叠态与展开态**：站点上 Experience 折叠时只放 Challenge→Impact 的一句缩写，
  完整 CSI 在展开态（ADR-0007 后果第 2 条）。简历没有折叠态，**硬上限是 1-2 行**。

## 超长怎么压

课程三节都写了 "Statements should be 1-2 lines long"。CSI 的天然倾向是越写越长，
所以压缩不是可选项。顺序固定，从上往下取，先能压的先压
（完整论证见 [ADR-0016](../adr/0016-course-conventions-scope.md) §3）：

1. 把 Challenge 写成从句，不单独占一个分句；
2. 删掉不承载取舍的技术细节（组件名、版本号、非关键中间步骤）；
3. Impact 只留最强的一个量，不并列三个数字；
4. 仍然超长 → 这条素材含两件事，**拆成两条**，别继续砍。

**不许压掉取舍。** 压掉它这条就退回 Action 的标准，等于不合格（ADR-0007 §1）。
压到最后取舍放不下的，换素材，不是降标准。

Professional Profile 段的条目要比 Experience 里更短：
同一条素材在 profile 里是结论，在 Experience 里才是完整 CSI。
