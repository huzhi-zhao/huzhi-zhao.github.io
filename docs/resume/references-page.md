# 推荐人页

- 依据：DPS 51019 `Cultivating Strong References`、[ADR-0013](../adr/0013-public-repo-privacy-boundary.md)、[ADR-0014](../adr/0014-resume-scope-in-docs.md)
- 适用：只在雇主索要时提供的那一页

## 结论先行：这一页的内容永远不进本仓库

推荐人页上逐条都是**第三方个人的姓名、职位、雇主与联系方式**——
正是 [ADR-0013](../adr/0013-public-repo-privacy-boundary.md) 约束 1 明令不得出现在公开仓库里的东西。
而且它们不是我的信息，是**别人托付给我的信息**，泄露的代价由他们承担。

因此：

| 东西 | 放哪 |
| --- | --- |
| 推荐人页的**写法与规范**（本文） | 本仓库 `docs/resume/` |
| 推荐人的**真实姓名与联系方式** | ToucanShelf `Career/Contacts/People/` |
| 成稿的推荐人页文件 | 本人本地，与简历 PDF 同处，**不进任何仓库** |

本文里出现的任何人名都是虚构的（FR-11.5）。

## 规则

- **简历上不写推荐人**，也**不写 "References available upon request"**。
  雇主知道你有推荐人，需要时会开口。写这句话等于用一行版面说了一句废话。
- **单独一页**，与简历、求职信用**同一套版式**（见下文"一套版式"）。
- **只在被要求时提供**：招聘广告里点名要，或面试之后。
  不要随每份申请一起投出去。
- **数量 3 到 5 人。** 少于 3 不够，多于 5 是噪音。
- **提供之前必须先征得本人同意。** 未经同意就把别人的手机号交出去，
  这件事本身就会毁掉那段关系。

## 谁可以，谁不可以

| 类型 | 是谁 | 能不能 |
| --- | --- | --- |
| Professional | 在工作场景里共事过的人：同事、主管、经理、高层；客户、供应商 | ✅ 首选 |
| Character | 认识你但没共事过的人：同学、讲师、教练、导师、志愿活动负责人 | ✅ 可用 |
| — | 配偶 / 伴侣、家人、朋友 | ❌ 绝对不行 |

**国际推荐人可以用。** 这条对我直接相关：九年经历全部在中国，
推荐人自然也在中国。课上明确说了国际推荐人成立。

实操上要预判两件事，写在每条推荐人下面：
**时差**（写清对方可接受的联系时段）和**语言**（对方能不能用英语通话；
不能的话，注明偏好邮件）。课件给的字段里本来就有 preferred contact method
和 preferred contact time，对跨国推荐人来说这两栏不是可选项。

## 每条要写的字段

```
姓名
职位
所在机构
电话 · 邮箱
偏好联系方式 · 偏好联系时间
```

## 用法

- 面试结束后**主动通知推荐人**：告诉他们可能会接到哪家公司的电话。
- 给推荐人**准备一份备忘**：提醒他们我们一起做过什么项目、我当时负责哪块。
  别指望别人记得三年前的细节——这一步直接决定推荐电话的质量。
- 面试结果**回告推荐人**，拿到工作后**道谢**。
- 职业往前走，**持续收集新的推荐人**。

## 和本仓库其它约定的关系

- **一套版式**：简历、求职信、推荐人页、感谢信共用同一套字体、字号、页边距与页眉。
  课件原文是 "Extend formatting across all self-marketing materials"。
  这是 [ADR-0007](../adr/0007-copy-conventions.md) §2 的关键词一致性在**视觉层**的对应物：
  词一致是让人记住一个印象，版式一致是让四份文件读起来出自同一个人。
- **推荐人名单的维护属于 ToucanShelf**，不属于本仓库。
  按 [ADR-0014](../adr/0014-resume-scope-in-docs.md) 约束 2，这里只放方法，不放事实。
