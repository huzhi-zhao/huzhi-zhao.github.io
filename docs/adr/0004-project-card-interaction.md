# ADR-0004 项目卡片：单一入口与信息分层

- 状态：已接受
- 日期：2026-08-20
- 依赖：[ADR-0002](0002-information-architecture.md)、[ADR-0005](0005-content-tiers-and-hosting.md)

## 背景

当前 `components/projects.tsx` 的卡片存在几个结构性问题：

- 用 Aceternity `3d-card` 实现，hover 触发 3D 倾斜；
- 卡面直接铺 4–5 行英文正文（`body`），三张卡并排就是一面文字墙；
- 视觉位（`visual`）只是 CSS 渐变色块，没有真实图像；
- 卡底挂 1–2 个文字外链（Source Code / Live Demo / Client Website）；
- 卡片本身不可点击，没有"进一步了解"的主路径。

## 决策

### 1. 每张卡有且只有一个主点击目标（primary destination）

整张卡是一个链接。目标按项目选"最能自证的那个终点"，不强制统一：

| 项目 | 主目标 | 理由 |
| --- | --- | --- |
| Urban Ops | 知识库 wiki | 系统还没跑起来，文档是当前最强证据 |
| MES | Live Demo | 能摸到的系统 > 任何文字 |
| Icon Pipeline | 待定（App repo 或 wiki） | 取决于想让人看代码还是看产品 |

wiki 上线前，Urban Ops 暂指 GitHub README；这意味着 **README 要当门面写**，
架构图放最上面。

### 2. 卡面信息压到五个元素，正文全部移走

```
图（16:9）
[问题域标签]              [状态徽章]
标题
问题句（一行，疑问句形式）
技术栈（最小号、最淡）
```

`body` 那种长段落从卡面移除，归属地是 wiki。

### 3. hover 层保留，但职责收窄

hover 显示的**不是项目介绍**，而是"我值不值得点进去"：25 词封顶、两行。
遮罩用底部渐变托住文字，占卡面高度约 40%，不整体糊掉图片。

### 4. 去掉 3D 倾斜

### 5. 次级链接从卡面移除

GitHub / Live Demo / Client Website 以及 MES 的"源码私有"说明，全部移到目的地页面。

## 理由

去掉 3D 倾斜的三条理由，按分量从重到轻：

1. **和"整卡可点"有实际冲突**。3D card 依赖 perspective 容器 + 内层多重 transform，
   把整卡包成链接后，倾斜状态下命中区域与视觉位置会错位——鼠标看着在卡上，点下去可能落空。
   这是功能缺陷，不是观感问题。
2. **和内容显隐抢同一个 hover 事件**。鼠标进入时卡片一边翻转一边浮字，两个动画叠加，
   哪个都读不清。
3. **信号与定位背离**。3D 倾斜传达的是"我会做炫酷前端"，而定位是后端/数据。
   一份数据工程作品集里，克制本身是专业性的一部分。

移除次级链接是因为链接套链接会产生真实缺陷：键盘 Tab 顺序混乱、屏幕阅读器读出嵌套结构、
移动端在链接与卡片交界处的点击结果不确定。

## 约束

1. **卡面正文字数硬上限**：问题句一行（不折行），hover 简介 ≤25 词。
   超了说明内容该进 wiki。
2. **卡内不得出现第二个链接元素**。若确需暴露源码入口，只允许右上角一个图标按钮，
   且必须 `stopPropagation` + 独立 `aria-label`；默认不做。
3. **hover 层在移动端不渲染**（而不是常显——常显会退化回文字墙）。
   移动端路径是"看图和问句 → 直接点进去"。
4. **图片设计约束**：卡图实际会被缩到约 400px 宽显示，因此一张图只能表达一个意思。
   Urban Ops 画 Bronze→Silver→Gold 三段加箭头即可，不要画完整架构图；
   MES 截取有代表性的单个模块并放大，不要整屏大盘缩图。字号要大到缩放后仍可读。
5. 状态徽章（In Progress / Production）保留——诚实标注比包装成完成品更可信。

## 后果

- 卡片承载的信息量显著下降，站点对**目的地页面质量**的依赖变强。
  这意味着 ADR-0005 里的 wiki 层不是可选项，是这套设计的前提。
- `components/ui/3d-card.tsx` 在 Projects 中不再使用（Hero 终端仍在用，见 ADR-0009）。
