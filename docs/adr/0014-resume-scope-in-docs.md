# ADR-0014 docs 承担简历工作的范围，以及为什么不拆桶

- 状态：已接受（2026-08-29 评审）
- 日期：2026-08-23（初稿）／ 2026-08-29（定稿）
- 依赖：[ADR-0001](0001-site-positioning.md)、[ADR-0007](0007-copy-conventions.md)、[ADR-0013](0013-public-repo-privacy-boundary.md)

## 背景

项目里已经沉淀了简历相关的方法论（DPS 51019 课程的版式与品牌框架、CSI 三段式、
Labour Market Research 的关键词方法），而且站点内容本身就是简历事实的另一种表达。
再开一个独立仓库做简历，等于把同一批事实维护两遍。

自然的做法是让 `docs/` 同时承担简历工作。随之而来两个问题：会不会推翻 ADR-0001？
`adr/design/launch` 要不要改成"项目桶 + 简历桶"的双桶制？

## 决策

### 1. docs 管方法论与可公开事实，不管敏感与无关素材

`docs/` 承担的是简历的**决策与方法论**：版式选型、改写规范、ATS 取舍、评审清单。
可公开的简历事实（时间线、公司名 / 职位名、技术栈）本来就在站点内容里，同样留在仓库。
敏感字段与和 portfolio 无关的素材按 [ADR-0013](0013-public-repo-privacy-boundary.md)
留在 ToucanShelf。

### 1.1 portfolio 是名片，简历是投递物

这两件东西的**受众与变更频率都不同**，这是本 ADR 的前提：

| | portfolio（huzhi.dev） | 简历（CV） |
| --- | --- | --- |
| 受众 | 所有人——招聘方、老师、朋友、刚认识的人 | 特定 employer |
| 措辞 | 一套，对谁都一样 | 按 JD 调整用词与侧重 |
| 变更 | 定稿后更新很少 | 每次投递都可能改 |

所以站点**不跟招聘方走**：不为某个岗位改写站点文案，不做"针对性版本"。
针对性发生在简历侧，站点是它的稳定坐标系。

**这不构成对 ADR-0001 的推翻。** ADR-0001 约束的是 huzhi.dev **站点**不做在线简历；
这里扩展的是**仓库 docs 目录**的用途。站点侧一切不变：不加简历板块，不提供 PDF 下载，
不为"看起来完整"补简历式内容。

### 2. 不开独立仓库，不拆双桶，保持单一 ADR 序列

**不为简历另开仓库。** 本仓库已经持有大量可公开的简历事实，
ToucanShelf MCP 又能补齐其余部分，两者合起来足够支撑简历工作；
再开一个仓库只会把同一批事实维护两遍，且要跨仓库执行一致性条款。
本仓库就是简历优化时 **Claude Code 协作的入口**。


新增内容目录，不改变现有轴：

```
docs/
  adr/            单一序列，站点与简历的决策混编
  design/         视觉与排版实现细节，简历版式文档进这里
  launch/         站点上线记录
  resume/         新增：简历方法论（版式选型、ATS 规范、改写清单）
  collaboration/  新增：与外部系统（ToucanShelf）的协作约定
```

## 理由

- **一致性条款是跨桶的。** ADR-0007 第 4 条把"站点 / CV / LinkedIn 三处事实必须对齐"
  写成了文案的前置条件，ADR-0001 约束 3 又说了一遍。拆桶等于把这条唯一防止两边漂移的
  规则劈成两半各自维护，半年后必然对不上——而"对不上"正是 ADR-0001 说的
  "直接摧毁可信度"。
- **简历是站点的坐标系，不是姊妹项目。** ADR-0001 定义站点时是相对 CV 定义的
  （"CV 给结论，站点给证据"）。坐标系不该另起一桶。
- ADR 之间的引用是自然跨主题的（0014 引 0001 和 0007）。加桶前缀只会制造跨桶引用。

## 约束

1. 简历相关的方向性决策进 `docs/adr/`，用同一套编号，不加前缀、不分子目录。
2. `docs/resume/` 只放方法论与规范。真实简历事实的唯一副本是站点内容
   （`lib/content/`），方法论文档引用它、不复制它。敏感与无关素材按 ADR-0013 不进仓库。
3. 不为简历新开仓库。复审条件见下。
4. 新增简历方法论文档前，先确认它不是 ToucanShelf `Career/PaceResumeCourse`
   已有内容的复制——课程原文留在知识库，`docs/` 只放**由它推导出的、约束后续工作的结论**。
5. 站点侧不因本 ADR 新增任何板块或下载入口，也不为特定 employer 做针对性改写。

## 后果

- 正面：简历与站点共用一套事实与一套关键词，一致性条款有单一执行点。
  简历方法论公开本身也是品牌资产。
- 负面：`docs/adr/` 会混着两类主题，浏览时需要靠标题分辨。
  若 ADR 数量超过约 25 篇且简历类占比过半，再考虑加索引分组（仍不拆目录）。

## 复审条件

若针对性简历版本多到需要版本管理（例如进入密集投递期，每个 JD 一版），
重新评估是否需要独立仓库——但那时首先要解决的是一致性条款如何跨仓库执行。
在那之前，答案是不开。
