# ADR-0009 全站动效预算

- 状态：已接受
- 日期：2026-08-20
- 依赖：[ADR-0004](0004-project-card-interaction.md)

## 背景

站点基于 Aceternity UI，组件库自带大量强动效：3D 倾斜卡片、spotlight、meteors、
globe、text-generate、resizable navbar。`components/ui/` 下已引入的组件多于实际使用的。

强动效对一份**后端 / 数据方向**的作品集是双刃剑：它传达的是前端表现力，
而不是定位所需要的工程克制。

## 决策

**全站只保留一处强动效：Hero 的终端组件（`hero-terminal.tsx`，含其 3D 卡片容器）。**

其余位置只允许"功能性微动效"：

- hover 上浮 ≤2px
- 边框/背景色的透明度过渡
- 图片 scale ≤1.03
- 进场 fade + 位移 ≤24px，且 `viewport once`

明确排除：3D 倾斜（Projects 卡片）、meteors、globe、大幅视差。

同时遵守 `prefers-reduced-motion`：该媒体查询开启时，所有位移/缩放类动效降级为纯透明度变化，
终端打字效果直接呈现最终状态。

## 理由

- 首屏放一个有性格的东西是合理的——终端符合 `.dev` 域名的气质，也符合后端工程师身份。
  但"全站到处都在动"给出的信号与定位背离。
- 单一强动效点还有注意力上的好处：只有一个动的东西时，它才真的被注意到。
- 移动端可整体关闭强动效而不损失信息（终端在窄屏可降级为静态文本块）。

## 约束

1. 新增强动效前，先说明它替换掉了哪一处现有动效——**预算是 1，不是"再加一个"**。
2. 未使用的 `components/ui/*` 组件不保留在仓库里，避免"既然装了不如用上"的惯性。
3. 动效不得承载信息：任何只有在动画完成后才能读到的内容，都必须有静态可读的等价形式。
