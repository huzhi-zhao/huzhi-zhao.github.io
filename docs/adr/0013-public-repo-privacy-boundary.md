# ADR-0013 公开仓库的隐私边界

- 状态：提议中（初稿）
- 日期：2026-08-23
- 依赖：[ADR-0001](0001-site-positioning.md)、[ADR-0005](0005-content-tiers-and-hosting.md)

## 背景

仓库是公开的（GitHub Pages 从这里发布）。此前 `docs/` 只放站点决策，泄漏风险低。
一旦 docs 开始承担简历工作（见 ADR-0014），风险性质就变了——简历工作天然要处理
真实时间线、离职原因、联系方式这类信息。

按字段做黑名单（手机号 / 具体住址 / 年龄 / 生日）是必要的，但不够。真正的风险是
**渐进泄漏**：离职时间、签证状态、薪资期望、某段经历的真实中断原因，单条都不像"敏感信息"，
拼起来是一份完整画像。`TODO.md` 里现有的几条事实不一致项（离职证明与 LinkedIn 时间不符、
career break）就是典型——它们是简历工作绕不开的事实，但绝不该留在公开仓库。

## 决策

**边界按"决策 vs 素材"划，不按字段划。**

| 层 | 内容 | 位置 | 公开性 |
| --- | --- | --- | --- |
| 方法论 | 版式选型、CSI 改写规范、ATS 取舍、关键词策略、评审清单 | 本仓库 `docs/` | 公开，且本身是品牌资产 |
| 素材与事实 | 真实 bullet、时间线细节、离职原因、联系方式、身份状态 | ToucanShelf 私有文档 | 永不进仓库 |
| 成品 | CV PDF / DOCX | 本地或私有分享链接 | `.gitignore`，站点不提供下载 |

这条边界的好处是**可执行**：不需要每次判断"这句算不算敏感"，只需要判断
"这是决策还是素材"。素材一律不进仓库，渐进泄漏就没有入口。

## 约束

1. **仓库内不出现**：手机号、街道地址、出生日期 / 年龄、身份与签证状态、
   薪资数字、第三方个人的姓名与联系方式。
2. **允许出现**：城市级位置（Winnipeg，ADR-0008 的求职意向表述需要它）、
   公开邮箱、公开的公司名与职位名、已在 LinkedIn 公开的时间粒度。
3. **不提供简历 PDF 下载**。站点不放下载入口，仓库不提交简历成品文件；
   `.gitignore` 显式排除简历产物目录。
4. 引用素材时**只引位置不引内容**——写"见 Career/Vault/Resume"，
   不把 bullet 原文粘进 `docs/`。
5. `TODO.md` 里的事实不一致项迁出仓库，只保留一句指针。

## 后果

- 正面：方法论可以放心公开（它本身是能力展示），素材有明确归属地，
  不用在每次提交前逐行自查。
- 负面：简历工作变成跨系统的——仓库读方法论、知识库读素材。
  这要求助手会话能同时访问两边（ToucanShelf MCP），单独 clone 仓库无法完成简历工作。
  这是接受这条边界要付的代价。

## 复审条件

若仓库转为私有，第 1、4 条可放宽；第 3 条（不提供 PDF 下载）属于 ADR-0001 的推论，
与公开性无关，不随之放宽。
