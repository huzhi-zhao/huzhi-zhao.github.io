# ADR-0013 公开仓库的隐私边界

- 状态：已接受（2026-08-29 评审，对初稿有修改）
- 日期：2026-08-23（初稿）／ 2026-08-29（定稿）
- 依赖：[ADR-0001](0001-site-positioning.md)、[ADR-0005](0005-content-tiers-and-hosting.md)

## 背景

仓库是公开的（GitHub Pages 从这里发布）。此前 `docs/` 只放站点决策，泄漏风险低。
一旦 docs 开始承担简历工作（见 ADR-0014），就要回答一个问题：什么进仓库，什么不进。

初稿曾把**渐进泄漏**（离职时间、经历中断原因等单条不敏感、拼起来是完整画像）
列为主要风险，并据此把一切"素材"划出仓库。评审时否掉了这个理由，见下。

## 决策

**边界按两问划：一问是否与简历相关，二问是否属于敏感字段。**

1. **与简历无关的内容，原则上不进仓库。** 仓库只承载简历里可公开的那部分：
   个人技术背景、个人项目、工作经历（含确切的起止与离职时间）。
   其余一切——课程原文、生活记录、与 portfolio 无关的资料——留在 ToucanShelf `Career/`。
2. **简历相关但属于敏感字段的，不进仓库。** 敏感字段是**具体位置（街道级住址）与手机号**。
   城市级位置、公开邮箱等不属敏感，可以公开。

| 层 | 内容 | 位置 |
| --- | --- | --- |
| 方法论 | 版式选型、CSI 改写规范、ATS 取舍、关键词策略、评审清单 | 本仓库 `docs/` |
| 可公开事实 | 技术栈、项目、公司名 / 职位名 / 起止与离职时间、城市、邮箱 | 本仓库（站点与 `docs/`） |
| 敏感字段 | 街道地址、手机号 | ToucanShelf，永不进仓库 |
| 无关内容 | 与 portfolio 无关的一切素材 | ToucanShelf，永不进仓库 |
| 成品 | CV PDF / DOCX | 本地或私有分享链接，`.gitignore` 排除 |

### 为什么不按渐进泄漏来设计

站点**不做主动分发**：本人不外发网址，也不会有人有动力代为推广。
需要说明的是，这不等于"没人能发现"——站点有完整 metadata 且未设 `noindex`，
搜索引擎可以索引它。但站上的内容本来就是会主动递给招聘方的简历事实，
被搜到不构成新的损失。

在这个前提下，为"陌生人拼接画像"这一威胁模型付出的成本（每条事实都要判断能不能写、
简历工作被迫跨系统）远大于收益。因此本 ADR 不以渐进泄漏为约束依据，
只挡明确的敏感字段。

## 约束

1. **仓库内不出现**：街道级住址、手机号。第三方个人的姓名与联系方式同样不出现
   （这是他人的隐私，不属本人可裁决范围）。
2. **允许出现**：城市级位置（Winnipeg）、公开邮箱、公司名与职位名、
   真实的起止与离职时间——包括尚未同步到 LinkedIn 的正确值。
3. **不提供简历 PDF 下载，且仓库不参与简历产物的生成**。
   站点不放下载入口；文本稿写入 ToucanShelf `Career/Vault/`，排版与导出在 Pages 中完成，
   产物不落在仓库任何位置（见下"简历的生成链路"）。`.gitignore` 仅作误放兜底。
   不提供下载这一条是 ADR-0001 的推论，与公开性无关。
4. 与简历无关的素材不进仓库；需要引用时**只引位置不引内容**
   （写"见 `Career/Vault/...`"，不粘原文）。

## 后果

- 正面：判据只有两问，可执行；简历事实与站点事实同处一地，
  ADR-0007 第 4 条的一致性检查不必跨系统。
- 负面：仓库里会长期存在真实的工作时间线。这是有意接受的——
  它本来就要出现在站点上。
- 仓库定位随之明确：**它是简历优化工作中 Claude Code 协作的入口**，
  持有全部可公开的简历事实；ToucanShelf 补充敏感与无关部分。

## 简历的生成链路

仓库只产出**文本内容**，不产出简历文件。完整链路（2026-08-29 定）：

1. 在本仓库与 Claude Code 协作，写出简历文本内容（依据站点事实与 `docs/resume/` 方法论）；
2. 文本稿写入 ToucanShelf `Career/Vault/`，那里是简历文本的唯一真源；
3. 本人对照 Vault 的文本稿，在 **Pages** 里改排版；
4. 从 Pages 导出 PDF；
5. 需要时把导出结果的文案交回 Claude Code 核对。

第 3、4 步是设计与体力活，文案定了之后不需要仓库或 ToucanShelf 参与。
**因此不约定 `resume-out/` 之类的产物目录——仓库里根本不该出现产物。**

## 复审条件

以下任一动作发生时，"不做主动分发"的前提失效，需重新评估渐进泄漏是否纳入约束：

- 把站点网址写进批量投递的简历或求职信；
- 为站点做 SEO 推广、投放，或提交到聚合目录；
- 把网址挂到公开的社交媒体主页。
