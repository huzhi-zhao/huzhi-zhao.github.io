# ADR-0003 作品集的分类轴：架构能力，而非业务域

- 状态：已接受
- 日期：2026-08-20
- 依赖：[ADR-0002](0002-information-architecture.md)

## 背景

按 ADR-0002，作品要按"问题"而不是"技术栈清单"组织。第一版的直觉分类是按**业务域**切：

- `City & Public Operations`（Urban Ops）
- `Industrial / Shop Floor`（MES）
- `Applied AI`（Icon Pipeline）

两个输入否定了这个切法。

**输入一：本地市场调研（2026-08）。** Manitoba 在招的数据/后端岗位集中在保险、金融、薪酬、
公用事业、大学、农业与医疗设备——Wawanesa（Senior Architect - Data & AI）、Payworks、
University of Manitoba、Siemens Healthineers，加上 Canada Life / Great-West、
Bold Commerce、SkipTheDishes。**没有一个属于"城市运营"域**；市政本身基本不从公开市场
招数据工程师。把最亮的项目打上 `City Operations` 标签，本地雇主读到的信号是域不匹配。
（调研方法与局限见 [设计文档 0001 附录](../design/0001-brand-revamp.md#附录调研记录2026-08)。）

**输入二：作品集的实际走向。** UOIP 只是大数据方向的热身。到毕业（2027-12）之前还会有
其他项目，例如 `ghostfolio-ai`（金融大数据方向）。也就是说**业务域本身是轮换的**：
市政 → 金融 → 制造。真正稳定不变的是跨项目复用的架构能力，而且这类能力不依赖工作环境，
在家就能练出来并拿出可验证的成果。

## 决策

**分类轴用架构能力，不用业务域。业务域降级为每个项目的叙事背景。**

标签集（初版，待 JD 调研收敛后定稿）：

| 标签 | 覆盖 | 业务域（仅作叙事背景） |
| --- | --- | --- |
| `Operational Data Platforms` | Urban Ops、（预计）ghostfolio-ai | 市政 / 金融 |
| `Industrial Systems` | MES | 制造 |
| `Applied AI` | Icon Pipeline | — |

品牌句锚点：把杂乱的多源真实数据，做成能支撑运营决策的可靠指标。
（英文侧对应 Elevator Pitch 中的 `turn complex, high-volume data into reliable operations`。）

## 理由

- 业务域轮换，架构能力不变。按域分类的作品集，每加一个新域就多一个孤立的分类，
  三年后是一堆互不相干的标签；按能力分类，新项目是**同一条主张的又一个证据**。
- 一个项目能否说服雇主，不在于域是否对口，而在于它证明的方法是否可迁移。
  UOIP 的价值是"多源、脏、真实、可公开核验的数据 → 分层建模 → 支撑调度决策的指标"，
  这套形状同样适用于 Wawanesa 的理赔、Payworks 的薪酬批处理、Canada Life 的保单数据。
  ghostfolio-ai 之后，"同一套方法在两个完全不同的域上都跑通了"本身就是更强的论据。
- 这条同时化解了输入一的风险：域不再出现在分类轴上，就不存在"域不匹配"的第一印象。

## 约束

1. 问题域标签**最多三个**。第四个标签出现时，说明作品集在发散，应先合并再新增。
2. 标签是分类轴，权重高于技术栈标签；技术栈标签保留但视觉降级（更小、更淡、在下方）。
3. **具体行业 / 城市名不得进入分类轴**，只能出现在项目正文、问题句和文章里。
4. 新项目落地时，先回答"它归到现有哪个能力标签下"。若三个都不合适，
   要么它不该进作品集，要么标签集本身需要复审——不允许顺手新增标签。
5. 标签措辞在 ≥8 份本地完整 JD 的关键词统计完成前视为**未定稿**，
   实现上必须集中在一处常量里，不得在多处硬编码（见设计文档）。

## 后果

- 正面：作品集可以持续加项目而不发散；本地雇主不会因域不对口而直接跳过。
- 负面：抽象层级抬高会损失具体性和记忆点。**缓解手段是卡片上的问题句**
  （"每场雪之后，哪个区先派铲雪车？"）——分类抽象、叙述具体。
  注意这不等于放弃"问题导向"：差异化仍靠具体问题讲出来，只是差异点是
  "同一套架构能力能解决不同域的问题"，而不是"我熟悉某个行业"。
- 本地化叙事（City of Winnipeg 公开数据）作为项目正文里的加分项保留，
  但不再承担分类职责，因此也不再是不可替代的——ghostfolio-ai 出来后它只是两个案例之一。

## 复审条件

- 完成 ≥8 份本地完整 JD 的关键词统计后，复审标签措辞。
- ghostfolio-ai 落地时，复审 `Operational Data Platforms` 是否仍能同时容纳市政与金融两个案例，
  还是需要更换措辞。
- 若求职地域从温尼伯转向其他市场，整条重新评估。
