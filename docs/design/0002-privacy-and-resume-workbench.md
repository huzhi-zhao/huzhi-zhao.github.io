- 日期：2026-08-23
- 对应决策：[ADR-0013](../adr/0013-public-repo-privacy-boundary.md)、[ADR-0014](../adr/0014-resume-scope-in-docs.md)
- 相关：[ADR-0005](../adr/0005-content-tiers-and-hosting.md)、[ADR-0009](../adr/0009-motion-budget.md)、[设计文档 0001](0001-brand-revamp.md)

## 1. 背景与范围

[设计文档 0001](0001-brand-revamp.md) 把 ADR-0002 ~ 0009 落成了 FR-1 ~ FR-8。
ADR-0013 与 ADR-0014 是这之后新增的两条决策，目前**只有决策没有需求**——
"素材不进仓库""docs 承担简历方法论"这两句话在仓库里没有任何东西在执行它们。

本文把这两条以及几处此前漏掉的可执行项，落成需求。编号接着设计文档 0001 往下走
（FR-9 起），因为两份文档共用一套 FR 命名空间。

**本文范围**

- 隐私边界从文档约定变成"提交前会拦住你"的东西；
- `docs/resume/` 目录的落地形态与首批文档清单；
- 与 ToucanShelf 协作中需要写进仓库的那部分；
- 站点侧"不因简历工作发生变化"的回归判据。

**明确不做**

- 不写与简历无关的素材、不写敏感字段（ADR-0013 约束 1、4）；
- 不在站点新增板块、路由或下载入口（ADR-0014 约束 4）；
- 不动设计文档 0001 里 P2 及之后的文案工作，那条线独立推进。

**前置条件已满足**：ADR-0013 与 ADR-0014 于 2026-08-29 转为"已接受"，FR-9 ~ FR-12 可开工。
注意 ADR-0013 定稿对初稿有修改，本文相应调整见 FR-9.2 ~ FR-9.5。

## 2. 需求

### FR-9 隐私边界的可执行化（ADR-0013）

- **FR-9.1** `.gitignore` 补简历产物排除规则，作为**误放兜底**：覆盖 `*.docx`、`*.pages`、
  常见的 `*[Rr]esume*.pdf` / `*CV*.pdf` 形态。
  **（2026-08-29 调整）** 不再约定 `resume-out/` 输出目录——按裁决，仓库完全不产出简历文件，
  排版与导出都在 Pages 中完成（ADR-0013"简历的生成链路"）。这条规则只挡
  "顺手把导出的 PDF 拖进仓库根"这一失误路径。
- **FR-9.2** 提供一个可手动运行的敏感信息扫描脚本（`scripts/privacy-scan.mjs` 或等价物），
  对 `docs/`、`lib/content/`、`components/`、根目录 markdown 做正则扫描：
  电话号码形态、街道地址关键词、第三方个人联系方式。
  **（2026-08-29 收窄）** ADR-0013 定稿把敏感字段限定为街道住址与手机号，
  出生日期 / 签证身份 / 薪资不再是扫描目标。
  **非 CI 强制**，与 FR-7.3 的链接检查脚本同一档次——目的是让自查成本接近零，不是设卡。
- **FR-9.3** 命中即报路径与行号，输出可直接跳转的 `file:line`；不自动修改文件。
- **FR-9.4** 白名单机制：城市级位置（Winnipeg）、公开邮箱、公开公司名与职位名
  不算命中（ADR-0013 约束 2）。白名单写在脚本里并注明依据的 ADR 条款。
- ~~**FR-9.5** 把 `TODO.md` 的"简历 / LinkedIn 待修正"整段迁往 ToucanShelf~~
  **作废（2026-08-29）**。该需求的依据是初稿的渐进泄漏模型与"约束 5"，两者在定稿中均已删除。
  这一节记的是待核实的事实误差——久远经历难以精确到月，属取证问题而非暴露面——
  且任职起止时间按 ADR-0013 约束 2 明确可公开。整段留在仓库。
- **FR-9.6** 简历成品的存放位置在仓库内不落地任何链接与路径——
  引用一律写"见 ToucanShelf `Career/Vault/`"（ADR-0013 约束 4）。

### FR-11 `docs/resume/` 工作台（ADR-0014）

### FR-13 站点侧不变的回归判据

ADR-0014 的核心承诺是"站点侧一切不变"。这个承诺需要可验证。

- **FR-13.3** 仓库内不出现简历成品文件（由 FR-9.1 的 `.gitignore` 与 FR-9.2 的扫描共同保证）。
- **FR-13.4** 以上三条并入 FR-11.2 的 `review-checklist.md`，作为每轮上线前的检查项。

## 3. 技术方案（初稿，粗颗粒）

### 3.1 检查脚本

`scripts/check.mjs` 一个入口，两个子检查：

- `links`：遍历 `lib/content/links.ts` 导出的 URL，HEAD 请求，
  按 `visibility` 标注判断匿名可达性是否符合预期（FR-7.2 / FR-7.3）。
- `privacy`：正则扫描（FR-9.2 ~ FR-9.4）。

均为 Node 原生实现，不引入依赖；`package.json` 加 `npm run check`。
不接入 CI——ADR 里这类检查的定位一贯是"降低自查成本"，不是门禁。

### 3.2 CV_HREF 的移除

`CV_HREF` 目前从 `site-navbar.tsx` 导出、被 `hero.tsx` 反向导入，
是一处组件间的意外耦合。删除时三处引用一并清理，不留常量。

### 3.3 `docs/resume/` 的写作顺序

建议顺序：`format-selection` → `csi-rewrite` → `review-checklist` → `ats-tradeoffs` → `master-vs-targeted`。
理由是前两篇产出后就能开始实际改写，后两篇是在改写过程中才知道该写什么。

## 4. 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 隐私扫描脚本误报多，最后没人跑 | 边界退回君子协定 | 白名单先行（FR-9.4）；宁可漏报也不要让首次运行刷屏 |
| 正则扫不出改写过的表述 | 敏感字段以自然语言混入 | 脚本是兜底不是边界，真正的边界是 ADR-0013 的两问判据 |
| `docs/resume/` 把站点内容里的事实又抄一遍 | 两处副本漂移，违反 ADR-0007 第 4 条 | ADR-0014 约束 2：方法论引用 `lib/content/`，不复制 |
| 方法论文档与 ToucanShelf 课程笔记重复 | 两边漂移 | ADR-0014 约束 3：仓库只放推导出的结论 |
